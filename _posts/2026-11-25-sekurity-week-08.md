# 보안 기초 용어
보안 분야를 이해하는 데 필요한 언어 익히기

> **학습 목표  **
> 사이버보안의 기본 용어를 이해하고, 공격과 방어의 차이, 보안 기술의 주요 분야, 보안 활동 및 대회의 목적을 구분한다.

# 1. 보안과 취약점

## 1.1. 해킹(Hacking)

정의: 컴퓨터, 프로그램, 네트워크 등의 동작 원리를 분석하고 이용해 특정한 결과를 만들어 내는 행위.

사이버 보안 분야에서는 주로 시스템의 보안 취약점을 발견하거나 이를 이용하는 활동을 의미한다.

예시

- 웹사이트의 로그인 기능에서 보안 문제를 발견한다.
    
- 프로그램의 오류를 이용해 원래 허용되지 않은 기능을 실행한다.
    
- 보안 전문가가 기업의 허가를 받아 시스템의 보안 수준을 점검한다.
    

핵심: 해킹이 모두 불법인 것은 아니다. 허가 받은 보안 점검과 무단 침해는 구분해야 한다.

## 1.2. 취약점(Vulnerability)

정의: 공격자가 악용할 수 있는 시스템이나 프로그램의 보안상 약점.

프로그램을 개발하거나 시스템을 설정하는 과정에서 발생할 수 있다.

예시

쇼핑몰에서 로그인한 사용자가 자신의 개인정보만 조회해야 하는데, 서버가 접근 권한을 검사하지 않는다고 가정하자.

```
정상적인 시스템

사용자 → 개인정보 요청
       → 서버에서 접근 권한 확인
       → 자신의 정보만 조회 허용
```

```
취약한 시스템

사용자 → 다른 사람의 개인정보 요청
       → 서버가 접근 권한을 확인하지 않음
       → 다른 사람의 개인정보 노출
```

핵심: 취약점은 공격 자체가 아니라, 공격에 이용될 수 있는 약점이다.

---
## 1.3. N-day 취약점

정의: 이미 외부에 알려진 보안 취약점. 일반적으로 공개된 취약점 중 아직 수정하지 않은 시스템에서 악용할 수 있는 문제를 말한다.

N은 취약점이 알려진 이후 경과한 시간을 나타내는 표현이다.

N-day를 이해하려면 Zero-day와 비교하면 쉽다.

| 구분        | Zero-day      | N-day                |
| --------- | ------------- | -------------------- |
| 취약점 공개 여부 | 아직 알려지지 않은 상태 | 이미 공개적으로 알려진 상태      |
| 보안 패치     | 일반적으로 아직 없음   | 이미 제공되었을 수 있음        |
| 주요 위험     | 알려지지 않은 약점 악용 | 알려진 약점을 수정하지 않아 악용당함 |

예시

1. 어떤 프로그램에서 취약점이 발견된다.
    
2. 개발사가 취약점을 수정하는 업데이트를 배포한다.
    
3. 일부 사용자는 프로그램을 업데이트하지 않는다.
    
4. 공격자가 공개된 취약점 정보를 이용해 업데이트하지 않은 프로그램을 공격한다.
    

이것이 대표적인 N-day 공격 상황이다.

단, N-day는 자료에 따라 패치가 이미 나온 취약점만 가리키기도 하고, 패치 여부와 관계없이 공개된 취약점 전체를 가리키기도 한다.

Vulnerability & Exposure Management

핵심: 이미 알려진 취약점이라도 시스템이 수정되지 않았다면 여전히 위험하다.

## 1.4. CVE(Common Vulnerabilities and Exposures)

정의: 공개된 개별 보안 취약점을 구분하기 위해 부여하는 표준 식별 번호 체계.

여러 기관과 보안 전문가가 동일한 취약점을 서로 다른 이름으로 부르면 혼란이 생길 수 있다.

이를 해결하기 위해 CVE 식별 번호를 사용한다.

예시

```
CVE-2024-3094
```

- `CVE`: 취약점 식별 체계
    
- `2024`: 식별 번호에 포함된 연도
    
- `3094`: 개별 취약점 식별을 위한 번호
    

이 번호는 실제로 알려진 XZ Utils 관련 취약점의 식별자다.

CVE 번호를 사용하면 어떤 프로그램의 어떤 취약점에 관한 이야기인지 정확하게 구분할 수 있다.

핵심: CVE는 공격 기술의 이름이 아니라 특정 취약점을 식별하는 번호 체계다.

## 1.5. CWE(Common Weakness Enumeration)

정의: 소프트웨어나 하드웨어에서 발생할 수 있는 보안상 약점의 유형을 분류하는 체계.

CVE와 가장 큰 차이는 다음과 같다.

- CVE: 실제 제품에서 발견된 특정 취약점을 식별한다.
    
- CWE: 취약점이 발생하는 약점의 종류를 분류한다.
    

예시

```
CWE-89
→ SQL 인젝션과 관련된 보안상 약점 유형
```

어떤 쇼핑몰 프로그램에서 SQL 인젝션 취약점이 발견되면, 그 개별 취약점에는 CVE 번호가 부여될 수 있고 취약점의 유형은 CWE-89로 분류될 수 있다.

핵심: CVE가 개별 문제의 식별 번호라면 CWE는 문제의 유형이다.

## 1.6. PoC(Proof of Concept)

정의: 발견한 취약점이나 공격 방법이 실제로 가능한지 증명하는 **개념 검증 과정** 또는 **결과물**.

보안 분야에서는 보통 취약점이 실제로 악용 가능한지 보여주는 짧은 코드나 재현 방법을 의미한다.

예시

보안 연구자가 웹사이트의 권한 검사 문제를 발견했다고 가정하자.

1. 취약점이 존재한다고 의심한다.
    
2. 허가된 테스트 환경에서 문제를 재현한다.
    
3. 권한이 없는 정보를 조회할 수 있다는 사실을 확인한다.
    
4. 재현 과정과 결과를 정리해 개발자에게 전달한다.
    

이때 작성한 재현 코드나 검증 방법이 PoC가 될 수 있다.

핵심: PoC는 어떤 보안 문제가 실제로 발생할 수 있음을 증명하는 데 사용된다. 반드시 완성된 공격 도구일 필요는 없다.

## 1.7. Chaining(체이닝)

정의: 여러 취약점이나 공격 기법을 연결하여 하나의 공격을 완성하는 방식.

하나의 취약점만으로는 큰 피해를 주기 어려워도 여러 개를 연결하면 더 심각한 결과가 발생할 수 있다.

예시

```
취약점 A
→ 일반 사용자에게 노출되면 안 되는 정보 발견
       ↓
취약점 B
→ 발견한 정보를 이용해 권한 검사 우회
       ↓
결과
→ 원래 접근할 수 없었던 중요 기능에 접근
```

핵심: 개별적으로 영향이 제한적인 취약점들도 연결하면 더 큰 보안 문제가 될 수 있다.

# 2. 공격과 방어

사이버보안은 크게 공격자의 관점에서 약점을 찾는 활동과 시스템을 보호하는 활동으로 구분할 수 있다.

## 2.1. Offensive Security(공격 보안)

정의: 공격자의 관점에서 시스템의 보안 취약점을 발견하고, 실제 악용 가능성을 검증하는 보안 분야.

주요 활동

-  공격 기법 연구
    
- 시스템의 보안 수준 검증
	
- 취약점 분석(Vulnerability Research)
    
- 모의해킹(Penetration Testing)
    
- 레드티밍(Red Teaming)
	

예시: 기업에서 보안 전문가에게 자사 웹사이트를 공격자의 관점으로 점검해 달라고 요청한다.

핵심: 공격 기술을 이용하지만, 보안 점검에서는 허가된 범위 안에서 시스템의 약점을 발견하고 개선하는 것이 목적이다.

## 2.2. Defensive Security(방어 보안)

정의: 사이버 공격으로부터 시스템과 데이터를 보호하고, 공격을 탐지하거나 대응하는 보안 분야.

주요 활동

- 네트워크 및 시스템 모니터링
    
- 침입 탐지 및 차단
    
- 보안 사고 분석
    
- 취약점 수정 및 보안 강화
    

예시: 기업의 보안 담당자가 비정상적인 로그인 시도를 발견하고 해당 접근을 차단한다.

핵심: 공격을 예방하고, 실제 공격이 발생했을 때 피해를 최소화하는 것이 목적이다.

## 2.3. 레드팀(Red Team)

정의: 실제 공격자의 행동을 모의하여 조직의 보안 체계가 얼마나 효과적으로 작동하는지 검증하는 팀.

단순히 취약점을 찾는 데 그치지 않고 실제 공격 상황을 가정하여 조직의 탐지 및 대응 능력까지 평가할 수 있다.

예시: 기업의 허가를 받은 레드팀이 외부 공격자를 모방하여 내부 시스템에 접근할 수 있는지 검증한다.

핵심: 공격자의 역할을 수행하여 조직의 보안상 약점을 확인하는 팀이다.

## 2.4. 블루팀(Blue Team)

정의: 사이버 공격으로부터 조직의 시스템과 데이터를 보호하고 공격을 탐지·대응하는 팀.

예시: 블루팀이 시스템의 보안 로그를 분석하다가 비정상적인 접속 시도를 발견하고 대응한다.

로그(Log)는 프로그램이나 시스템에서 발생한 활동을 기록한 데이터다.

핵심: 시스템을 방어하고 보안 사고에 대응하는 팀이다.

## 2.5. 퍼플팀(Purple Team)

정의: 레드팀과 블루팀이 협력하여 조직의 공격 탐지 및 방어 능력을 개선하는 활동 또는 협력 체계.

예시

```
레드팀
→ 모의 공격 수행
       ↓
블루팀
→ 공격 탐지 및 대응
       ↓
퍼플팀 활동
→ 공격 방법과 방어 결과 공유
       ↓
보안 체계 개선
```

퍼플팀은 반드시 별도의 조직을 의미하지는 않는다. 레드팀과 블루팀이 협력하는 활동 자체를 가리키기도 한다.

핵심: 레드팀과 블루팀의 협력을 통해 조직의 보안 수준을 높이는 방식이다.

## 2.6. 레드티밍(Red Teaming)

정의: 실제 공격자의 전략과 행동을 모방하여 조직의 전반적인 보안 대응 능력을 평가하는 활동.

레드팀은 이러한 활동을 수행하는 조직이나 인력을 가리키고, 레드티밍은 활동 자체를 의미한다.

예시

기업이 다음 상황을 가정해 보안 훈련을 진행한다.

1. 외부 공격자가 기업 시스템에 침입을 시도한다.
    
2. 레드팀이 허가된 범위에서 공격 과정을 모의한다.
    
3. 블루팀이 해당 활동을 탐지하고 대응한다.
    
4. 공격 성공 여부와 대응 과정의 문제점을 분석한다.
    

핵심: 실제 공격과 유사한 상황을 만들어 조직의 방어 체계를 검증하는 활동이다.

## 2.7. 보안관제(Security Monitoring / SOC)

정의: 시스템과 네트워크를 지속적으로 감시하여 사이버 위협을 탐지하고 대응하는 활동.

보안관제를 수행하는 조직이나 시설을 보안관제센터(SOC, Security Operations Center)라고 한다.

예시

```
서버 및 네트워크
       ↓
보안 로그 수집
       ↓
이상 징후 분석
       ↓
공격 의심 활동 발견
       ↓
보안 담당자 확인 및 대응
```

핵심: 사이버 공격이나 이상 징후를 빠르게 발견하고 대응하기 위한 활동이다.

## 2.8. 악성코드(Malware)

정의: 컴퓨터나 시스템에 피해를 주거나, 정보를 탈취하거나, 사용자가 원하지 않는 악의적인 동작을 수행하도록 만들어진 소프트웨어.

대표적인 종류

| 종류               | 설명                                 |
| ---------------- | ---------------------------------- |
| 바이러스(Virus)      | 다른 파일이나 프로그램에 붙어 확산할 수 있는 악성코드     |
| 웜(Worm)          | 스스로 복제하여 다른 시스템으로 퍼질 수 있는 악성코드     |
| 트로이목마(Trojan)    | 정상적인 프로그램처럼 위장하는 악성코드              |
| 랜섬웨어(Ransomware) | 데이터를 암호화하거나 접근을 차단하고 금전을 요구하는 악성코드 |

예시: 사용자가 정상적인 프로그램이라고 생각하고 파일을 실행했지만, 실제로는 개인정보를 탈취하는 악성코드가 실행된다.

핵심: 악성코드는 공격에 사용되는 악의적인 소프트웨어이며, 모든 해킹이 악성코드를 필요로 하는 것은 아니다.

# 3. 보안 분야

## 3.1. 웹 해킹(Web Hacking)

정의: 웹사이트와 웹 애플리케이션의 구조 및 동작을 분석하여 보안 취약점을 찾아내거나 악용하는 분야.

웹 애플리케이션은 브라우저를 통해 사용하는 프로그램이다.

주요 분석 대상

- 로그인 및 회원가입 기능
    
- 사용자 접근 권한
    
- 데이터베이스 연동 기능
    
- 웹 서버와 브라우저 사이의 통신
    

예시: 웹사이트에서 사용자의 권한을 제대로 확인하지 않아 다른 사람의 개인정보가 노출되는 문제를 발견한다.

핵심: 웹사이트와 웹 애플리케이션의 보안 취약점을 다루는 분야다.

## 3.2. 시스템 해킹(System Hacking)

정의: 운영체제와 시스템 프로그램의 동작을 분석하여 보안 취약점을 찾아내거나 악용하는 분야.

운영체제(OS)는 컴퓨터의 하드웨어와 프로그램 실행을 관리하는 기본 소프트웨어다.

주요 분석 대상

- Windows 및 Linux 운영체제
    
- 프로세스와 메모리
    
- 파일 접근 권한
    
- 시스템 프로그램
    

예시: 일반 사용자 권한으로 실행한 프로그램의 취약점을 통해 관리자 권한을 얻을 수 있는 문제를 분석한다.

핵심: 운영체제와 시스템 내부 기능의 보안 문제를 다룬다.

## 3.3. 디지털 포렌식(Digital Forensics)

정의: 컴퓨터나 디지털 기기에 남아 있는 데이터를 수집하고 분석하여 사건의 원인과 과정을 조사하는 분야.

예시

기업 서버에서 해킹 사고가 발생했다고 가정하자.

1. 사고가 발생한 서버의 관련 데이터를 확보한다.
    
2. 접속 기록과 파일 변경 내역을 분석한다.
    
3. 공격자가 언제 어떤 활동을 했는지 조사한다.
    
4. 분석 결과를 바탕으로 사고 과정을 재구성한다.
    

이때 증거가 훼손되지 않도록 데이터를 보존하는 것이 중요하다.

핵심: 디지털 흔적을 분석해 사건에서 무슨 일이 발생했는지 확인하는 분야다.

## 3.4. 리버싱(Reverse Engineering)

정의: 완성된 프로그램을 분석하여 내부 구조와 동작 원리를 알아내는 기술.

일반적인 프로그램 개발은 설계와 소스코드를 바탕으로 실행 프로그램을 만든다.

리버싱은 반대 방향에서 접근한다.

예시: 소스코드가 없는 프로그램을 분석하여 특정 기능이 어떤 조건에서 실행되는지 파악한다.

리버싱으로 원래 소스코드 전체를 정확하게 복원할 수 있는 것은 아니다.

핵심: 완성된 프로그램을 분석하여 내부 동작 원리를 알아내는 기술이며, 악성코드 분석과 취약점 연구에도 사용된다.

## 3.5. IoT 해킹(Internet of Things Hacking)

정의: 인터넷에 연결되는 사물인터넷(IoT) 기기와 관련 시스템의 보안 취약점을 분석하는 분야.

IoT는 인터넷을 통해 데이터를 주고받거나 원격으로 제어할 수 있는 기기와 기술을 의미한다.

대표적인 대상

- 스마트홈 기기
    
- IP 카메라
    
- 스마트 도어락
    
- 인터넷 연결 가전제품
    
- 각종 센서 및 제어 장치
    

예시: 인터넷에 연결된 IP 카메라의 인증 기능에 문제가 있어 허가받지 않은 사용자가 카메라 영상에 접근할 가능성을 분석한다.

핵심: 일반 컴퓨터뿐 아니라 인터넷에 연결된 다양한 기기의 보안 문제를 다루는 분야다.

# 4. 활동과 대회

## 4.1. 버그바운티(Bug Bounty)

정의: 기업이나 기관이 외부 보안 연구자에게 자사 서비스의 취약점을 발견하고 제보하도록 허용하고, 조건에 따라 보상을 지급하는 제도.

동작 과정

```
기업이 버그바운티 프로그램 운영
       ↓
보안 연구자가 허용된 범위에서 취약점 탐색
       ↓
취약점 발견 및 제보
       ↓
기업이 취약점 확인
       ↓
조건 충족 시 보상 지급
```

예시: 기업이 자사 웹사이트의 보안 취약점을 제보하는 연구자에게 보상을 제공한다.

단, 모든 취약점 제보에 보상이 지급되는 것은 아니다. 프로그램마다 허용된 점검 범위와 보상 조건이 다르다.

핵심: 허가된 범위에서 취약점을 발견하고 제보하면 보상을 받을 수 있는 제도다.

## 4.2. CTF(Capture The Flag)

정의: 보안 문제를 해결하거나 주어진 시스템을 분석하여 정답인 플래그(Flag)를 획득하는 사이버보안 대회.

플래그는 문제를 해결했다는 것을 증명하기 위한 특정 문자열이다.

예시

```
보안 문제 제공
       ↓
프로그램 또는 시스템 분석
       ↓
취약점 발견 및 문제 해결
       ↓
Flag 획득
       ↓
정답 제출 및 점수 획득
```

핵심: 보안 지식과 문제 해결 능력을 실습을 통해 검증하는 대회다.

## 4.3. A&D(Attack & Defense)

정의: 참가팀이 자신의 시스템을 방어하면서 다른 팀의 시스템을 공격하는 방식의 CTF 대회.

일반적인 문제 풀이형 CTF와 달리 공격과 방어를 동시에 수행한다.

예시

```
A팀                         B팀

자신의 서버 방어              자신의 서버 방어
       ↑                            ↑
       │                            │
       └──── 서로 공격 수행 ────────┘
```

진행 과정

1. 각 팀에 취약점이 존재하는 서버와 서비스가 제공된다.
    
2. 참가자는 자신의 서버에서 취약점을 발견하고 수정한다.
    
3. 동시에 다른 팀의 서버에 존재하는 취약점을 이용해 플래그 획득을 시도한다.
    
4. 공격 성과와 방어 상태, 서비스 정상 작동 여부 등에 따라 점수가 결정된다.
    

대회마다 세부 규칙과 점수 계산 방식은 달라질 수 있다.
