## **네트워크 기초**

**1. 네트워크의 기본 요소**
- IP 주소와 PORT

IP 주소: 네트워크에 연결된 모든 장치가 가지는 고유한 인터넷상의 주소
PORT: 한 컴퓨터 안에서 실행 중인 여러 프로그램 중 특정 네트워크 앱을 구분하는 번호

- DNS (Domain Name System)

사람이 기억하기 어려운 숫자로 된 IP 주소를 `https://www.google.com` 같은 문자 형태의 도메인 이름으로 변환해 주는 시스템
양방향 조회 가능.

- 패킷과 응용계층

패킷: 네트워크를 통해 송수신되는 데이터의 기본 전송 단위
커다란 파일이나 데이터를 한 번에 보내면 네트워크를 독점하고 에러 처리가 어렵기 때문에, 작은 조각(패킷)으로 나누어 전송한다

응용 계층: 네트워크 계층 구조 중 최상단에 위치하며, 사용자가 사용하는 애플리케이션과 직접 소통하는 계층.
컴퓨터 랜선이나 Wi-Fi(하위 계층)는 단순히 `0`과 `1`이라는 전원 신호만 이동시킬 뿐, 이 데이터가 "웹페이지 요청"인지 "이메일 전송"인지 알지 못함.
응용 계층은 이 데이터를 사람이 이해할 수 있는 "목적에 맞는 화면과 메시지 형태"로 바꾸고 규칙을 정해주는 역할. 

**웹 서핑을 할 때**: 웹페이지 문서를 주고받는 규칙 $\rightarrow$ **HTTP / HTTPS**
**이메일을 보낼 때**: 편지를 보내고 받는 규칙  $\rightarrow$ **SMTP / IMAP**
**파일을 다운로드할 때**: 대용량 파일을 안전하게 전송하는 규칙 $\rightarrow$ **FTP**

전송계층: 응용계층에서 생성한 메시지를 패킷으로 나누고 목적지 포트번호(ex:443번)라벨을 붙임
인터넷계층: 전송계층에서 포장된 패킷에 목적지 ip주소 라벨을 붙임
네트워크 Access계층: 완료된 데이터를 0,1의 전기신호로 바꾸어 랜선이나 wifi로 쏘아올림

**클라이언트가 데이터를 보낼때**
응용계층->전송계층->인터넷계층->네트워크Access계층
**서버가 데이터를 받아서 검사할떄**
네트워크Access계층->인터넷계층->전송계층->응용계층

- Client / Server의 차이

Client는 서비스를 요청하는 주체 / Server는 요청을 받아 처리 후 응답하는 주체
필요할때만 접속하여 데이터를 받는다 / 항상 대기 상태로 요청을 기다린다
클라이언트가 서버에 요청한다는것은? 예를들어 웹페이지 접속(조회요청-get)/ 로그인(데이터 제출 요청-post)/ 검색어 입력(데이터 검색 요청-get)/파일사진 업로드(파일 전송 요청-post)

GET, POST: 클라이언트가 서버에 목적을 알리는 HTTP Method의 대표적인 두가지 종류. HTTP Message에 나타난다.

**2. 웹 통신**
- HTTP와 HTTPS

HTTP(HyperText Transfer Protocol): 인터넷에서 데이터를 주고받기 위한 기본적인 규칙
중간에 누군가 패킷을 훔쳐보면 아이디, 비밀번호, 결제 정보 등이 그대로 노출된다
HTTPS (HTTP Secure): HTTP + SSL(Secure Sockets Layer)/TLS(Transport Layer Security) 암호화 방식
데이터를 보내기 전에 암호화하여 전송하므로, 중간에서 패킷을 도청하더라도 내용을 읽을 수 없다.

- URL의 구조

URL (Uniform Resource Locator)은 인터넷상에 있는 파일, 페이지 등의 위치를 나타낸다.
ex)
`https://www.google.com:443/search?q=burp#section1`
`https://` : Protocol 통신 규약
`www.google.com` : Domain(Host) 접속할 서버 컴퓨터의 문자 주소
`:443` : Port 서버 내 서비스 접속 창구
`/search` : Path 서버 내 자원이나 페이지의 위치
`?q=burp` : Query String 서버에 전달하는 추가 데이터 (?키:값)
`#section1` : Fragment 페이지 내 특정 위치(앵커)로 이동

- HTTP message

클라이언트와 서버가 주고받는 메시지는 텍스트 형태로 이루어져 있으며, (클라이언트->서버)요청(Request)과 (서버->클라이언트)응답(Response)이 있다
요청

start line에는 http method와 URL의 경로, query string 그리고 http 프로토콜 버전이 포함됨

응답

응답에서의 상태코드
200 OK : 성공. 요청이 정상처리됨
302 Found : 리다이렉트. 다른 주소로 이동시킴
403 Forbidden : 거부. 권한이 없어서 접근 불가능
404 Not Found : 없음. 요청한 페이지나 자원을 찾을 수 없음
500 Internal Server Error : 서버 에러. 서버 내부 프로그램에 오류 발생

- Cookie와 Hash

Cookie: 서버가 클라이언트(브라우저)에 저장해 두는 아주 작은 텍스트 데이터입니다.
HTTP 프로토콜은 상태를 기억하지 않는 특징이 있다. 요청을 한 번 주고받으면 접속이 끊겨 다음 요청 시 잊어버린 상태로 있다.
로그인 유지, 사용자 방문 기록 등을 유지하기 위해 사용. 브라우저는 서버에 요청을 보낼 때마다 가지고 있던 쿠키를 헤더에 담아 자동으로 전송한다.

Hash: 임의의 길이의 데이터를 입력받아 고정된 길이의 고유한 문자열(해시값)로 변환하는 단방향 암호화 기술
입력값 $\rightarrow$ 해시값 변환은 가능하지만, 해시값 $\rightarrow$ 원래 입력값 복원은 불가능.
원본 데이터에서 단 1글자나 마침표 하나만 바뀌어도 결과 해시값은 완전히 다른 문자열로 바뀜

**클라이언트가 서버에 요청하는 과정**
사용자가 클라이언트(웹 브라우저)에 google.com 을 입력 ->응용 계층 프로토콜(HTTPS)을 이용해서 HTTP Message를 생성한다 -> 전송계층에서 HTTP Message를 작은 패킷으로 나누고 목적이 포트번호(443)를 붙인다 -> 인터넷 계층에서 DNS조회를 통해 알아낸 목적지의 서버 IP주소를 붙인다-> 네트워크 Access계층에서 완성된 패킷 데이터를 0,1의 전기신호로 변환하여 랜선이나 wifi로 쏘아올림 -> 서버가 이를 받아 화면을 응답

**서버가 클라이언트에 응답하는 과정**
네트워크 Access 계층에서 전기신호를 받아서 디지털 데이터로 복원->인터넷계층에서 IP주소를 확인하여 자사 서버로 온 패킷임을 검증 -> 전송계층에서 포트번호를 확인하여 해당 포트를 열고 웹 서버 프로그램으로 패킷 조각들을 순서대로 합쳐 전달 -> 응용계층에서 최종 복원된 HTTP Message를 읽고 DB조회나 회원가입,로그인 검증 등의 로직을 처리 -> 웹 서버 프로그램이 처리결과를 바탕으로 HTTP Message를 만든다 -> 요청떄와 마찬가지고 4계층부터 1계층까지 진생하며 클라이언트로 보냄

**클라이언트의 응답 수신, 화면 출력**
클라이언트가 서버의 HTTP Message 응답을 받아 1계층에서 4계층으로 진행 -> 상태코드가 200인지 확인 -> Header확인. Content-Type를 확인하여 본문 데이터가 HTML문서임을 파악 -> Body 랜더링. body 구역에 들어있는 HTML/CSS/JS 코드를 읽어 사용자가 눈으로 보는 웹페이지 화면으로 렌더링해서 보여준다.

* Content-Type
	HTTP 메시지의 Body에 들어있는 데이터가 어떤 형식(파일 종류)인지 알려주는 헤더 정보
* Body 랜더링 
	`Body` 영역에 들어있는 텍스트 코드들을 읽어서 웹사이트 화면으로 변환

**3. Burp Suite 사전 준비**
- Burp Suite 설치하기

- 실습 : 본인이 서버에 보낸 패킷 열어보기 (Burp Suite)
	화요일 오프라인 모임에서 함께 진행 · HTTP 요청·응답 관찰 (약 20분) Burp Suite 내장 브라우저에서 웹페이지에 접속하고, 자신이 보낸 HTTP 요청과 서버의 응답을 열어봅니다. Method·Path·Header·Cookie·Body를 찾아봅니다.
- 학습 목표
	클라이언트와 서버의 통신을 이해하고, Burp Suite에서 자신의 HTTP 요청·응답 확인

Method: 서버에 요청하는 동작의 종류
	`GET` (조회), `POST` (생성/제출), `PUT` (수정), `DELETE` (삭제)
Path: 서버 내에서 접근하려는 자원,페이지의 경로
	`/` (메인), `/login`, `/search?q=burp` (쿼리 스트링 포함)
Header: 요청에 대한 부가적 정보(키:값)
Cookie: 서버가 나를 식별하거나 로그인 상태를 유지하기 위해 전송하는 값
Body: 서버로 보낼 실제 데이터 본문
