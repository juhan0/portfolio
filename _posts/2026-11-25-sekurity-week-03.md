Python과 데이터 처리

### 1. 변수와 기본 자료형

- 변수란 무엇이며, Python에서 변수에 값을 저장하는 방법
	변수는 데이터를 메모리에 저장하고 필요할때 불러서 사용할 수 있도록 이름을 붙인 데이터 상자이다.
- 다음 기본 자료형의 차이와 해당 자료형들의 간단 사용 예시
	
- `type()`으로 값의 자료형 확인하기
	
- `int()`, `str()`, `float()`을 이용한 자료형 변환
	
- 문자열 `"404"`와 정수 `404`의 차이
	문자열 "404"는 글자 데이터이다. 덧셈 연산 시에 문자열 연결이 된다.
	정수 404는 숫자 데이터이다. 덧셈 연산 시에 수학적 계산이 된다.
- `==`는 무엇을 비교하며, `=`와 어떻게 다른지 알아보기
	= 는 할당 연산자. 오른쪽 값을 왼쪽의 변수에 저장, 대입할때 사용
	`==`는 비교 연산자. 두 값을 비교할때 사용하며 결과로 True Flase를 반환한다.
- 다음 코드의 실행 결과와 각 변수의 자료형 확인하기
	
	status = "404" 
	count = 3 
	is_error = int(status) >= 400  
	
	print(status, type(status)) 
	print(count, type(count)) 
	print(is_error, type(is_error))`
	
	

### 2. 조건문과 반복문

- `if`, `elif`, `else`의 실행 흐름
	if문: 조건의 참,거짓을 판단하고 True이면 실행하고 조건문을 종료한다
	elif문: 이전 조건들이 모두 False일 때 다음 조건을 검사한다.
	else문: 위의 모든 조건이 False일 때 실행되는 예외 처리이다.
- 비교 연산자와 논리 연산자 알아보기
    - `==` 같음 
    - `!=` 다름
    - `<` 미만
    - `>` 초과
    - `<=` 이하
    - `>=` 이상
    - `and` 두 조건이 모두 True 일 떄 True
    - `or` 두 조건중 하나라도 True 이면 True
    - `not` 조건의 결과의 반대
- `in`을 이용해 문자열이나 자료구조에 값이 포함되어 있는지 확인하기

- `for`문과 `while`문의 차이
	for문은 데이터의 처음부터 끝까지 하나씩 꺼내며 반복한다.
	while문은 조건이 True인 동안만 코드를 반복하고 False가 되면 멈춘다.
- `range()`와 `enumerate()`를 사용하는 이유
	반복문에서 여러번 반복하기 위해 사용.
	range는 숫자를 순서대로 만들어서 반복
	enumerate는 리스트 값과 인덱스를 동시에 사용
- `break`와 `continue`의 차이
	break는 실행 즉시 반복문 전체를 강제 종료
	continue는 현재 순번의 나머지 코드를 실행하지 않고 뛰어넘은 뒤 다음 반복 순서로 넘어간다.
- Python에서 들여쓰기가 문법의 일부라는 말의 의미
	파이썬은 들여쓰기를 통해 코드가 어느 블록에 속하는지 결정한다.
- 다음 목록에서 400 이상인 상태 코드만 출력해 보기

- 함수를 사용하는 이유
	여러 과정을 거쳐야 할 때 함수로 나눠서 과정을 저장해 놓으면 더 깔끔하게 정리할 수 있고, 수정도 쉬울 것 같다.
	[파이썬 함수 완전 정리 – 함수 정의, 호출,.. : 네이버블로그](https://blog.naver.com/housework8762/223895967263) --> 코드가 짧아지고 가독성이 좋아지고 유지보수도 편해진다. 효율적이다
- 함수의 매개변수와 반환값
	매개변수는 함수가 외부로부터 값을 전달 받는 변수.
	반환 값은 함수가 내부 로직을 수행한 후 호출한 곳으로 돌려주는 최종 결과 값.
- `print()`와 `return`의 차이
	print는 결과를 화면에 출력해서 보여주는 것. 
	return은 함수의 결과를 함수 밖으로 돌려주는 것.
- 하나의 함수가 너무 많은 일을 처리하면 수정과 테스트가 어려워지는 이유
	하나의 함수가 여러 일을 처리하면 코드가 길어지고 거로 연결된 부분이 많아져서 한 부분을 수정했을 때 다른 부분에 영향을 줄 가능성이 커지고 어느 부분에서 오류가 발생했는지 찾기 어려움.
- 다음과 같이 로그 분석 작업을 함수로 나누면 어떤 장점이 있는지 생각해 보기
    - 한 줄을 해석하는 함수
    - 집계 결과를 갱신하는 함수
    - 최종 결과를 출력하는 함수
    각 함수가 하나의 역할에 집중하기 떄문에 코드의 이해와 수정이 쉬워진다. 또한 특정 기능에 문제가 생겼을 때 해당 함수만 따로 테스트 하거나 수정할 수 있다.
    로그 분석 작업: 프로그램이나 서버가 남긴 기록을 읽어서 필요한 정보를 뽑아내는 작업.
- 예외와 프로그램 오류의 관계
	예외는 프로그램을 실행하는 중에 예상하지 못한 상황이 발생했을 때 나타나는 오류이다.
	예외가 발생하면 프로그램이 정상 실행되지 않을 수 있지만 try-except를 사용하면 예외를 처리하고 프로그램을 계속 실행할 수 있다.
- `try`, `except`, `else`, `finally`가 각각 언제 실행되는지 알아보기
	try 실행을 시도할 코드
	except try에서 예외가 발생했을 떄
	else 예외가 발생하지 않았을 떄
	finally 예외 발생 여부와 관계없이 마지막에 실행
- 다음 예외가 발생하는 상황을 간단히 정리하기
    `ValueError` 자료형은 맞지만 값이 적절하지 않을 때
    `KeyError` 딕셔너리에 존재하지 않는 키를 사용할 떄
    `IndexError` 리스트에 존재하지 않은 인덱스에 접근할 떄
    `FileNotFoundError` 존재하지 않는 파일을 열려고 할 때
    `UnicodeDecodeError` 파일의 문자 인코딩을 잘못 해석하여 문자를 읽을 수 없을 떄
    
- 모든 오류를 `except:`로 무조건 숨기면 문제의 원인을 찾기 어려운 이유
	모든 예외를 처리(Exception)해 버리면 어떤 문제가 발생했는지 알 수 없다. 구체적으로 예외 처리하면 예외 상황별로 다른 복구 로직을 수행 가능하다
- 다음 목록을 정수로 변환하되, 변환할 수 없는 값은 건너뛰어 보기
	`values = ["200", "404", "ERROR", "500", "-"]`
	# numbers리스트에 문자열인 i를 int형으로 저장. 값오류가 나면 넘어감.
	

### 4. list·dictionary·stack·queue

 list와 dictionary
- `list`와 `dictionary`의 차이
	list는 여러값을 순서대로 저장하는 자료형. 인덱스로 데이터에 접근
	dictionary는 데이터를 key:value 형태로 저장. key를 이용해서 데이터에 접근
- `list`가 순서대로 여러 값을 저장할 때 적합한 이유
	리스트는 값마다 인덱스가 정해져있기 때문에 여러값을 순서대로 저장하기 편하다.
- `dictionary`가 `key: value` 형태의 데이터를 저장할 때 적합한 이유
	어떤 값인지 이름을 붙여서 봐야 할 때 편리하다.
- 다음 조작 방법 알아보기
    `list`: 
    - `append()` 리스트 마지막에 값을 추가
    - `pop()` 리스트에서 마지막 값을 삭제
    - 인덱싱 특정 위치(인덱스)의 값을 가져오는 것
    - 슬라이싱 리스트의 일부분을 가져오는 것 `A[1:4]`
    `dictionary`:
    - 값 추가·수정  `get()` `keys()` `values()` `items()` 

- 존재하지 않는 key를 `data[key]`로 조회할 때와 `data.get(key)`로 조회할 때의 차이
	그냥 `data[key]`는 없는 값이면 오류(KeyError)가 나지만 `data.get(key)`는 없는 값을 찾을 떄 None을 반환한다
- dictionary를 이용해 값의 등장 횟수를 세는 방법
	
	# count 딕셔너리에 numbers의 값들을 추가. 없으면 0으로 시작하고 있으면 그 값에 1을 추가 한다

##### stack과 queue

- stack의 LIFO와 queue의 FIFO가 무엇을 의미하는지 알아보기
	stack의 LIFO = Last In, First Out
	마지막에 들어온 것이 가장 먼저 나온다
	queue의 FIFO = FIrst In, First Out
	먼저 들어온 것이 먼저 나온다
- Python `list`의 `append()`와 `pop()`으로 stack을 표현하는 방법
	
- queue를 만들 때 `collections.deque`를 사용하는 이유
	앞에서 데이터를 꺼내는 작업이 더 효율적이기 때문
	그래서 list.pop(0)보다 collections.deque 이 더 효율적이다.
- `deque`의 `append()`와 `popleft()` 사용법
	
	append는 뒤에 추가. popleft는 앞에서 뺀다.
- 큰 queue에서 `list.pop(0)`을 반복하는 방식이 비효율적인 이유
	pop(0)은 맨 앞의 값을 삭제한 다음 나머지 데이터를 앞으로 한 칸씩 이동 시킨다. 데이터가 커질수록 더 비료율적이게 된다.
- stack과 queue가 실제로 사용될 수 있는 예시를 각각 하나씩 찾아보기
	stack = 웹 브라우저의 뒤로가기 = 가장 최근에 방문한 웹부터 처리한다.
	queue = 프린터 작업 = 먼저 요청된 문저부터 처리한다.

### 5. 문자열·bytes와 파일 읽기

- Python의 `str`과 `bytes`의 차이
	str은 사람이 읽는 문자열
	bytes는 컴퓨터가 다루는 데이터
- `str.encode()`와 `bytes.decode()`가 각각 하는 일
	문자열을 바이트로 변환
	byte를 문자열로 변환
- `"가".encode("utf-8")`의 결과와 byte 수 확인하기
	
	
- 텍스트 모드 `"r"`와 바이너리 모드 `"rb"`의 차이
	파일 내용을 문자열로 읽는다.
	파일 내용을 bytes로 읽는다.
- 텍스트 파일을 열 때 `encoding="utf-8"`을 명시하는 이유
	파일의 문자를 어떤 방식으로 해석할지 지정.
- `with open(...) as f:` 형태로 파일을 열면 좋은 이유
	이 형태를 사용하면 파일을 사용한 뒤 자동으로 닫는다.
	with : 파일 작업이 시작될 때 자원을 할당하고 작업이 끝나면 자동을 파일을 닫게 해준다.
	open() : 지정한 경로의 파일을 열어서 파일 객체를 생성
	as f : 생성된 파일 객체를 f라는 이름의 변수에 할당.
	기존의 방식대로 하면  끝낼 때 f.close()를 호출해야하고 만약 close전 read()도중에 에러가 발생하면 close에 도달하지 못하고 튕기면서 파일이 열린 채로 메모리에 남아버리는 현상(메모리 누수, 파일 잠김 현상)이 일어난다.
- `read()`, `readline()`, `readlines()`의 차이
	파일 전체를 읽는다/ 한 줄만 읽는다/ 파일의 모든 줄을 리스트로 가져온다
	*read()왜 쓰지?? : read를 쓰지 않아도 for문 등으로 파일을 인식하고 출력이 가능하다. read()는 파일의 전체 내용이 하나의 변수로 필요할 때. ex)파일 안에 특정 단어 찾기 혹은 정규표현식을 적용할 떄.
	
- 큰 로그 파일을 한 번에 모두 읽는 것보다 한줄씩 처리하는 방식이 유리한 이유
	큰 로그 파일을 한번에 읽으려면 메모리를 많이 사용하게 된다. 한 줄씩 처리하면 메모리를 적게 사용 가능.
- `strip()`과 `rstrip("\n")`의 차이
	앞뒤의 공백, 줄 바꿈 등을 모두 제거.
	맨 뒤의 `\n`만 제거
- `split()`으로 한 줄을 여러 필드로 나누는 방법
	split() 괄호 안에 있는 문자를 기준으로 문자열을 나눈다. 아무것도 없으면 공백이 기준. 나눠진 문자열들은 리스트로 반환
- 다음 코드를 실행하고 `text`와 `raw`의 자료형 및 출력 결과 확인하기
	text = "로그"
	raw = text.encode("utf-8")
	restored = raw.decode("utf-8")
	print(text, type(text))
	print(raw, type(raw))
	print(restored, type(restored))

### 6. 정규표현식

- 정규표현식을 사용하는 이유
	정규표현식이란 문자열에서 특정한 패턴을 찾거나 검사하기 위한 규칙. 
	복잡한 텍스트를 확인할때 일반 조건문을 사용하는것보다 효율이 좋다.
- 일반 문자열 검색과 정규표현식 검색의 차이
	일반 문자열 검색은 특정 문자열만 찾지만 정규표현식은 숫자로 이루어진 부분 전체를 찾을 수 있다.
- Python에서 정규표현식을 작성할 때 raw string인 `r"..."`을 자주 사용하는 이유
	`\`를 먼저 해석하지 않고 정규표현식에 그대로 전달하기 위해. `r`이 없는 일반 문자열에서는 `\`가 파이썬의 이스케이프 문자로 사용될 수 있어서 정규표현식이 복잡해질수록 헷갈릴 수 있다.
	일반 문자열에서 `\n`은 파이썬이 줄바꿈으로 인식하지만 r"`\n`" 으로 쓰면 `\`와n을 그대로 전달한다.
	
- 다음 기호가 나타내는 기본적인 의미 알아보기
    - `.` 아무 문자 하나
    - `^`, `$` 문자열의 시작과 끝
    - `*`, `+`, `?` 앞의 패턴이 0, 1, 0또는1번 이상 반복
    - `[]` 여러 문자 중 하나 ex) `[0-9]` 숫자 하나
    - `()` 여러 패턴을 하나의 그룹으로
    - `\d`, `\w`, `\s` 숫자 / 문자, 숫자, _ / 공백 문자
	
- `re.search()`, `re.match()`, `re.fullmatch()`, `re.findall()`의 차이
	문자열 전체를 읽으며 처음 일치하는 곳을 탐색
	문자열의 시작 부분부터 패턴이 일치하는지 탐색
	문자열 전체가 패턴과 모두 일치하는지 확인
	문자열 전체에서 일치하는 모든 부분을 탐색, 리스트로 반환

- 캡처 그룹과 `group()`이 무엇인지 알아보기
	
	캡쳐 그룹은 ()로 묶어서 문자열의 특정 부분을 따로 저장하고 꺼내는 기능.
	
	group()을 사용하면 정규 표현식으로 매칭된 결과를 가져올 수 있다.
- 반복해서 사용할 패턴을 `re.compile()`로 미리 만드는 이유
	re.compile()은 같은 정규표현식 패턴을 여러 번 사용할 때 미리 만들어 두는 것.
	사용하면 실행할떄마다 문법을 해석하지 않고 해석 과정을 1회만 거쳐서 속도가 빨라진다.
	ex) `re.compile(r"\d+") . search(text1) . group()`
	re.compile(r"`\d+`") : `\d+` 패턴을 미리 만듦
	search(text1) : text1에서 숫자(`\d+`)를 찾음
	group() : 찾은 결과를 가져옴
- 아래 문자열에서 정규표현식으로 상태 코드와 IPv4 주소 형태를 찾아보기
	`2026-09-20 09:12:10 ERROR 192.168.0.11 POST /login 401`
	
	`\b` 숫자의 앞뒤에 다른 글자나 숫자가 없이 독립된 단어인지 확인
	`[1-5]` 처음 숫자가 1부터 5중 하나인지 확인
	`\d{2}` `\d`는 숫자, 뒤에 숫자가 2번 반복.
	$ 앞부터 찾으면 192가 출력 됨. 앞이 아닌 맨뒤부터 찾는다
	{1,3} 1자리에서 3자리 사이의 숫자
	`(?:\.\d{1,3}){3}` . 뒤에 숫자 1~3자리 숫자, 이그룹이 3번 반복
 	

> 위 IPv4 패턴은 `999.999.999.999`도 찾을 수 있습니다. 문자열의 **형태를 찾는 것**과 실제로 유효한 IP 주소인지 **검증하는 것**은 다른 문제니, 참고 바랍니다~

※ 공백으로 정확히 구분된 단순한 로그는 `split()`만으로도 처리할 수 있습니다. 모든 문자열 처리를 억지로 정규표현식으로 해결할 필요가 없는 이유도 생각해 보면 좋습니다.
	split()은 단순 문자를 기준으로 잘라내는 C 언어 기반의 단순 선형 탐색 방식이라 속도가 매우 빠르고 메모리를 적게 쓴다.
    정규표현식은 패턴 분석, 오토마타(State Machine) 구성, 백트래킹(Backtracking) 등의 복잡한 내부 연산을 거치므로 단순 연산에 사용하면 불필요한 성능 손실이 생긴다.
