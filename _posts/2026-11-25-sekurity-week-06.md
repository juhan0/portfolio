Docker : 애플리케이션을 빠르게 구축, 시험 및 배포할 수 있게 해주는 소프트웨어 플랫폼

# 1. Dockerfile
- Dockerfile 문법

Dockerfile : Docker 이미지를 생성하기 위한 자동화된 작성 스크립트.
	`FROM` : 베이스 이미지 지정. 이미지 생성의 기본 환경설정을 설정
	 ex) `FROM python:3.11`
	`WORKDIR` : 작업 디렉터리 설정. 이후 실행될 명령들의 기준 경로가 된다.
	 ex) `WORKDIR /app`
	`COPY` : 호스트 컴퓨터의 파일, 디렉터리를 이미지 내부 경로로 복사
	`ADD` : `COPY`와 비슷한 기능 + 압축 파일 자동 해제 및 URL 다운로드
	`RUN` : 이미지 빌드 중에 실행될 명령어를 입력하여 레이어 생성, 패키지 설치
	`ENV` : 이미지 내부에서 사용할 환경 변수를 설정 `\`를 이용해서 여러개의 환경변수 한번에 지정 가능. 이미지 빌드 및 컨테이너 실행 중에도 필요한 변수
	`ARG` : 이미지를 빌드하는 동안에만 필요한 변수
	`EXPOSE` : 컨테이너가 수신 대기할 포트 선언
	 ex) `22` (SSH), `80` (HTTP 웹), `443` (HTTPS 보안웹), `3306` (MySQL)
	`CMD` : 컨테이너 실행 시 기본으로 호출될 명령어
	 ex) `CMD ["python3", "main.py"] `
	`ENTRYPOINT` : 컨테이너 실행 시 고정으로 수행될 명령어

- 이미지를 빌드하는 과정
1. 빌드 명령 실행 `docker build` -t my-app:1.0 .
	`-t [이미지이름]:[태그] [빌드 컨텍스트 경로]`
	`-t` (tag) : 생성될 이미지에 이름과 태그를 붙이는 옵션
	`.` : 빌드 컨텍스트 경로로, Dockerfile과 복사할 소스 파일들이 위치한 현재 디렉토리를 의미
	
Docker Daemon : 사용자가 명령을 내리면 데몬이 이를 받아 처리
2. 빌드 컨텍스트 전송
	- Docker CLI는 지정된 경로(`.`)에 있는 모든 파일과 폴더를 읽어 압축한 뒤 Docker 데몬(`dockerd`)으로 전송
	- Docker 데몬은 이 파일들을 받아서 `COPY`나 `ADD` 명령어가 실행될 때 참조할 원본 데이터로 준비
3. 레이어 단위 단계별 실행
	- Docker 데몬은 `Dockerfile`을 첫 줄부터 한 줄씩 읽으면서 순차적으로 읽기 전용 레이어(Read-Only Layer)를 쌓아 올립니다.
4. 캐시 메커니즘 활용
	- **레이어 재사용:** 빌드 시 이전 빌드에서 만들어둔 레이어가 동일하고 변경사항이 없다면, 도커는 명령어를 다시 실행하지 않고 저장되어 있던 기존 레이어 캐시를 그대로 재사용함
	- 수정된 명령어 아래부터 캐시가 무효화되어서 다시 빌드하기 때문에 자주 바뀌지 않는 명령어를 상단에 배치
5. 최종 이미지 태그 지정 및 생성 완료
	- Dockerfile의 마지막 줄까지 실행이 완료되면, 모든 레이어들이 하나로 묶임
	- 지정한 이름과 태그(`my-app:1.0`)가 최종 레이어의 ID에 매핑됨
	- 독립적으로 즉시 실행 가능한 Docker 이미지 완성

# 2. Docker 명령어

- docker build : `docker build -t app:1.0 .`
	*Dockerfile을 읽어 새로운 Docker 이미지를 생성
- docker image : `docker image ls` / `docker image rm app:1.0`
	*로컬에 존재하거나 다운로드된 이미지 목록을 조회하고 관리(삭제, 정보 확인 등)
- docker run : `docker run -d -p 8080:80 app:1.0`
	*이미지를 바탕으로 새로운 컨테이너를 최초 1회 생성하고 실행
- docker exec : `docker exec -it my-container bash`
	*이미 만들어져 실행 중인 컨테이너 내부로 들어가 명령어를 추가 실행
- docker rmi : `docker rmi my-app:1.0`
	이미지를 삭제
- dokcer rm : `docker rm my-container`
	컨테이너를 삭제
- docker ps 
	현제 동작중인 컨테이너의 목록과 상태 확인

- 포트 공개(-p)와 호스트 포트·컨테이너 포트
	외부에서 컨테이너 내부 서비스에 접근하려면 호스트 컴퓨터의 포트와 컨테이너 내부 포트를 연결(포트 바인딩) 해야 한다
	`docker run -d -p [호스트 포트]:[컨테이너 포트] [이미지명]`
	- **`-d` 사용 :** 웹 서버(Nginx, Node.js 등), DB 서버(MySQL, Redis 등)처럼 24시간 끊김 없이 백그라운드에서 계속 켜두어야 하는 서비스
	- **`-d` 미사용:** 앱 실행 초기 로그나 에러 메시지를 눈으로 바로 확인하며 디버깅(테스트)할 때
- docker exec와 SSH 접속의 차이
	docker exec : 호스트에서 컨테이너 내부 프로세스를 직접 제어
	SSH 접속 : 네트워크를 거쳐 원격 가상 머신(서버)에 안전하게 접속

- Docker Volume : 컨테이너가 삭제되서나 재시작되어도 데이터를 영구적으로 저장하고 보존하기 위해 사용하는 도커 전용 저장소 메커니즘

# 3. Docker Compose

- docker-compose가 무엇인지 조사하기
	**docker-compose**는 여러 개의 Docker 컨테이너를 하나의 그룹으로 묶어서 한 번에 정의하고 실행할 수 있게 해주는 도구
- Dockerfile과 docker-compose의 차이
	dockerfile은 하나의 이미지를 빌드하기 위한 설계도 작성, docker-compose는 다중컨테이너 환경을 한번에 정의하고 실행.

# 4. SSH와 원격 접속

- SSH의 역할과 로컬 터미널·원격 셸의 차이
	SSH : 네티워크를 통해 다른컴퓨터에 안전하게 접속할수있는 프로토콜
	로컬터미널 : 내컴퓨터의 운영체제를 직접 제어하는 텍스트 입력창
	원격 셸 : SSH 등의 네트워크 연결을 통해 접속한 상대방 컴퓨터의 텍스트 제어 창
	`ssh [사용자 계정]@[호스트 주소] -p [포트 번호]`
	ssh testuser@localhost -p 2222
- 접속 대상의 사용자 계정·호스트 주소·포트
	사용자 계정 : 접속 대상 컴퓨터에 등록된 로그인 아이디
	호스트 주소 : 접속할 대상 컴퓨터의 네트워크 위치
	포트: 대상 컴퓨터 내에서 SSH서비스가 기다리고 있는 통로 번호
- SSH 클라이언트와 SSH 서버의 역할
	클라이언트 : 원격 접속을 요청하는 쪽
	사용자가 입력한 명령어를 암호화하여 서버로 전달하고 서버가 보낸결과 화면을 받아 모니터에 출력
	서버 : 원격 접속을 수신하고 응답하는 쪽
	컨테이너 백그라운드에서 실행중인 서비스 데몬. 클라이언트 접속 요청을 받아 계정, 비밀번호를 검증하고 인증 성공하면 쉘에 열어 명령을 실행
- 비밀번호 인증과 최초 접속 시 호스트 키 확인의 의미
	계정 비밀번호를 입력하여 계정의 소유자가 맞는지 증명하는 사용자 신원확인 단계

`yes`를 입력하면 호스트의 지문이 내 컴퓨터의 파일에 저장되며, 이후 재접속 시에는 이 키를 비교하여 중간자 공격(Man-in-the-Middle)을 자동으로 감지하고 방지

#### 사전 실습 · Bandit SSH 접속 (10–15분) 
1. 공식 안내를 확인하고 개인 PC의 터미널에서`ssh bandit0@bandit.labs.overthewire.org -p 2220`을 실행합니다.
2. 공식 실습 계정 bandit0, 비밀번호 bandit0으로 로그인합니다.
3. whoami → hostname → pwd → ls → cat readme를 실행해 접속한 서버·계정·현재 위치를 확인합니다.
4. exit로 종료하고 로컬 터미널로 돌아옵니다. 
5. 접속 명령에서 사용자·호스트·포트를 구분하고 접속 전후의 차이를 정리해옵니다. 다음 단계 비밀번호는 보고서에 적지 않습니다.
bandit0 : 사용자
bandit.labs.overthewire.org : 호스트
-p : 포트옵션
2220 : 포트번호

접속전에는 터미널이 내 컴퓨터(로컬머신)를 직접 제어하는상태.
접속 후에는 내 터미널이 네트워크를 통해 원격 서버의 셸과 연결됨.
접속후 실행한 명령어들은 원격 서버 환경에서 처리되어 그 결과만 내 모니터 출력으로 돌려받음

Bandit SSh 서버는 'OverTheWire(오버더와이어)'라는 글로벌 해킹·보안 교육 단체(워게임 사이트)가 무료로 열어둔 연습용 서버

#### 실습

화요일 오프라인 모임에서 함께 진행 · Docker 컨테이너 만들기와 SSH 접속
1. 스터디장을 따라 Dockerfile을 작성하고 이미지를 빌드합니다. 
2. SSH 서버와 실습용 계정이 준비된 컨테이너를 실행하고 SSH 포트를 호스트에 공개합니다. 
3. 개인 PC의 터미널에서 실습용 사용자·호스트 주소·공개 포트로 SSH 접속합니다. 접속 정보는 현장에서 안내합니다. 
4. whoami → hostname → pwd를 실행하고 exit로 접속을 종료합니다. 
5. Bandit 접속과 비교해 접속 대상·계정·포트가 어떻게 바뀌었는지 설명하고 docker exec와 SSH 접속의 차이를 정리합니다.
